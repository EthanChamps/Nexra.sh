# Live cheap-model chat title generation — Design

**Date:** 2026-07-02
**Status:** Approved (brainstorming), pending spec review
**Milestone context:** M3a follow-up (live LLM agent has landed; this closes a
seam explicitly deferred by the M1 design below).

## Problem

`docs/superpowers/specs/2026-07-01-instant-new-chat-design.md` shipped a
deterministic mock (`deriveTitle()` in `nexra/src/state/reducer.ts`) as an
explicit **stand-in** for real behaviour: "the chat title is generated by the
cheapest model tier ... from the first question the user asks — the same
pattern as ChatGPT/Claude auto-titling." That design says M2 "swaps the mock
for a real cheap-model call without moving the seam."

The live agent (`electron/services/agent.live.ts`, M3a) has since landed, so
that seam is ready to fill. This design replaces the mock title call with a
real, cheap, non-blocking model call. **Focus (phase) inference is out of
scope** and is left exactly as-is (`inferFocus()` stays a keyword heuristic).

## Product behaviour

Unchanged from the M1 design: a new chat starts named "New chat". On the
user's first message, the chat is retitled automatically. A chat the user has
already renamed is never retitled. Only the first message triggers this.

What changes: the title now comes from a real model call instead of a
first-six-words heuristic, and — because that call is asynchronous — the
title appears a moment after the message is sent rather than instantly. This
matches ChatGPT/Claude's own UX (title fills in shortly after the first
message, without blocking the reply).

## Design

### Model choice

Reuse whatever provider/model is already configured in Settings for the main
chat (`loadConfig()` in `main.ts`) — no separate "cheap tier" setting. This
works identically for Anthropic and Ollama and avoids a hardcoded model id
that would need maintenance. (Considered: hardcoding a fixed cheap Anthropic
model like `claude-haiku-4-5`, truer to "cheapest tier" wording, but rejected
— it would require an Anthropic key even when the user's configured provider
is Ollama, and drifts out of date as model ids change.)

### Data flow

The reducer is pure and cannot make the model call itself, so generation
moves to `nexra/src/ipc.ts`, alongside the existing `agent.send` orchestration:

1. **Reducer** (`nexra/src/state/reducer.ts`):
   - `appendUserMessage` no longer sets `chat.name` via `deriveTitle`. It
     keeps setting `phaseId` via `inferFocus` (unchanged, out of scope).
   - New action `{ t: 'setChatTitle'; chatId: string; title: string }`: sets
     `chat.name = title` only if the chat is still provisional
     (`name === 'New chat'`). This preserves the existing guard — a chat the
     user renamed while the call was in flight is never overwritten.
   - `deriveTitle()` stays exported and pure, but its role changes from "M1
     stand-in" to "fallback used when the live title call fails."

2. **`ipc.ts`** `sendMessage()`: before dispatching `appendUserMessage`,
   compute whether this is the chat's first user message on a still-
   provisional chat (same check the reducer used to do internally). If so,
   after dispatching the user message and kicking off `agent.send`, also
   fire `window.nexra.agent.title(...)` — **not awaited**, runs concurrently
   with the streaming reply, never delays or blocks it:
   - On success: `dispatch({ t: 'setChatTitle', chatId, title })`.
   - On failure (rejected promise — no key, network error, provider error):
     silently fall back to `dispatch({ t: 'setChatTitle', chatId, title: deriveTitle(text) })`.
     No error banner; this is a cosmetic background feature and failure must
     never block or disrupt the chat.

3. **Main process** — new `nexra/electron/services/agent.title.ts`:
   ```ts
   export interface AgentTitleRequest { engagementType: string; text: string }
   export async function runTitle(req: AgentTitleRequest, cfg: ProviderConfig): Promise<string>
   ```
   Uses `generateText` (not `streamText` — one short completion) from the
   `ai` SDK via the existing `resolveModel(cfg)`. System prompt:

   > "Generate a short title (3–6 words) summarizing what this
   > {engagementType} security-consulting chat will be about, based on the
   > user's first message. Title Case, no quotes, no trailing punctuation, no
   > explanation — respond with only the title."

   `maxOutputTokens` capped small (~20) for speed/cost. Output is trimmed,
   stripped of wrapping quotes, and length-capped (~48 chars) as a safety net
   against a model ignoring instructions — mirrors `deriveTitle`'s own
   cleanup.

4. **`main.ts`**: `ipcMain.handle('agent:title', async (_ev, req) => runTitle(req, loadConfig()))`.
   Reuses `loadConfig()` exactly as `agent:send` does. Errors propagate as a
   rejected invoke — no special handling needed here, the renderer's
   `.catch()` covers it.

5. **`preload.ts`**: add `agent.title: (req) => ipcRenderer.invoke('agent:title', req)`.

6. **`agent.types.ts`**: add the `AgentTitleRequest` interface (above).

### Error handling

Single fallback path: any rejection from `window.nexra.agent.title(...)` —
missing API key, `resolveModel` throw, network/provider error — falls back to
`deriveTitle(text)`. No retries. No user-visible error. A user's own chat
message send/response flow is completely unaffected by title-call failures.

## Testing

Follows the existing Vitest conventions (`nexra/test/`, jsdom environment,
`ai`-module mocking style from `agent.live.test.ts`/`providers.test.ts`).

- **New `agent.title.test.ts`**: mock `generateText` and `resolveModel`
  (mirroring `agent.live.test.ts`'s `vi.mock('ai', ...)` pattern). Cover:
  prompt/system-message shape (engagementType interpolated), output
  trimming/quote-stripping/length-cap, and that a `resolveModel`/provider
  error rejects `runTitle`.
- **`reducer.test.ts` updates**: replace the assertions that
  `appendUserMessage` synchronously sets `chat.name` via `deriveTitle` with
  direct tests of the new `setChatTitle` action — sets title on a provisional
  chat; refuses to override an already-renamed chat. Keep `deriveTitle` unit
  tests (word-capping, punctuation cleanup, empty-input fallback) since it's
  still exported and used as the fallback. `inferFocus` tests are untouched.
- **New `ipc.test.ts`** (none exists today — first renderer-level test in
  this repo to stub `window.nexra`): cover `sendMessage`'s title-trigger
  branch only — fires `agent.title` exactly when the message is the first
  user message on a provisional chat (not on later messages, not on an
  already-renamed chat), dispatches `setChatTitle` with the resolved title on
  success, and dispatches `setChatTitle` with the `deriveTitle` fallback on
  rejection.

## Out of scope

- Focus/phase inference (`inferFocus`) — stays the existing keyword
  heuristic, untouched.
- Persistence of chat titles — chats are still in-memory only (per
  `docs/superpowers/HANDOVER.md`); unrelated to this change.
- A dedicated "cheap tier" model setting — reuses the single configured
  model per provider (see Model choice above).

## Fidelity note

No new UI surfaces. The only visible change is the title text filling in a
moment after the first message instead of instantly — no new styled
components, so `CLAUDE.md`'s design-reference fidelity rule doesn't apply
here.
