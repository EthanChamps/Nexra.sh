# Instant chat creation (no picker modal) — Design

**Date:** 2026-07-01
**Status:** Approved (brainstorming), pending spec review
**Milestone context:** Redcell M1 (UI shell, mock backends). See `docs/superpowers/HANDOVER.md`.

## Problem

Clicking **+ New Chat** currently opens `NewChatModal`, which forces the user to
pick a **Focus** (phase), a **Chat name**, and a **Background colour** before a
chat exists. None of this should be required. A user should click **+ New Chat**
and get a chat immediately under that engagement. The chat's name is decided for
them (renamable later); focus and colour get sensible defaults.

## Product intent (real behaviour, M2)

In the shipped product the chat **title is generated by the cheapest model tier**
(e.g. Haiku) from the **first question the user asks** — the same pattern as
ChatGPT/Claude auto-titling. Focus is likewise **inferred from context** rather
than picked up front.

M1 has **no live LLM** (mock backends only), so M1 simulates this deterministically.
The mock is a stand-in for exactly the M2 model call, wired at the same hook point
(first user message), so M2 swaps the mock for a real cheap-model call without
moving the seam.

## Behaviour

Clicking **+ New Chat** (Workspace header, or a Sidebar engagement's `+`) creates
a chat immediately under that engagement and selects it — no modal. The new chat:

- **Name:** `"New chat"` (provisional)
- **Focus:** none (empty `phaseId`)
- **Colour:** neutral default `#0a0b0d`

On the user's **first message**, a mock "AI" retitles the chat and infers its
focus, simulating the M2 cheap-model title call + context inference.

## Changes

### 1. Remove the modal and dead state

- Delete `src/components/modals/NewChatModal.tsx` and its render site in
  `src/screens/Workspace.tsx`.
- Remove UI state fields `newChatOpen`, `newChatName`, `newChatFocus`,
  `newChatColor` (`src/state/types.ts`, initial state in `src/state/reducer.ts`).
- Remove actions `openNewChat`, `closeNewChat`, `setNewChatName`,
  `setNewChatFocus`, `setNewChatColor` from the `Action` union and reducer.

### 2. `createChat` becomes the direct trigger

- `createChat` takes an optional `engId`: `{ t: 'createChat'; engId?: string }`.
  - Resolve engagement: `a.engId || U.activeEngagementId`; bail if none.
  - Set that engagement active (Sidebar can create under a non-active engagement),
    prepend the new chat, mark `updated`, select it.
- Both `+ New Chat` triggers dispatch `createChat` directly:
  - `Workspace.tsx` header `+ New Chat` → `dispatch({ t: 'createChat' })`.
  - `Sidebar.tsx` per-engagement `+` → `dispatch({ t: 'createChat', engId: p.id })`.

### 3. `makeChat` defaults

`makeChat` no longer takes name/focus/colour from user input:

- `name` → `"New chat"`
- `phaseId` → `''` (no focus)
- `color` → `'#0a0b0d'`
- **Greeting** becomes generic (no phase reference):
  > "I'm the agent for this {engagement type label}. Ask me to enumerate
  > configuration, run automated checks, or log findings — this chat keeps its
  > own context."
- `tools` unchanged (they come from the engagement type config, not the phase).

### 4. Mock titling + focus inference (first user message)

In the `appendUserMessage` reducer case, after pushing the user message: if the
chat is still **provisional** (name `=== 'New chat'` AND this was its first user
message), derive and set:

- **Title** — from the message text: trim, take the first ~6 words, strip
  surrounding punctuation, cap length. Fall back to `"New chat"` if the message
  has no usable words. (Stand-in for the M2 cheap-model title call.)
- **Focus** (`phaseId`) — keyword-match the message against the engagement's phase
  labels; fall back to the engagement's first phase.

Both derivations are **pure and deterministic** (no `Date.now`, no randomness) so
they are unit-testable. Guards:

- A chat the user has already **renamed** (name `!== 'New chat'`) is never
  retitled.
- Only the **first** user message triggers this; later messages do not re-title
  or re-infer.

Helper functions (e.g. `deriveTitle(text)`, `inferFocus(text, phases)`) live
alongside the reducer and carry a comment marking them as the M1 stand-in for the
M2 cheap-model call.

### 5. Graceful-empty UI (focus not yet inferred)

Three call sites render a focus chip via `phaseLabel(eng, chat.phaseId)`. When
`phaseId` is empty:

- **ChatPane** (`src/components/ChatPane.tsx`): hide the focus chip (`:75`);
  composer placeholder drops the phase → `"Message the agent…"` (`:34`).
- **Sidebar** (`src/components/Sidebar.tsx`): omit the per-chat focus label
  (`:27`) when empty.
- **ContextPanel** (`src/components/ContextPanel.tsx`): hide the focus row (`:33`)
  when empty (or render `—`).
- **ipc.ts** (`:57`): already passes `phaseLabel(...)` (empty string) to the mock
  agent — tolerant, no change needed beyond confirming the mock handles `''`.

## Testing

Follow the existing reducer-test style (project currently 20/20).

- `createChat` produces a provisional, focus-less, neutral chat and selects it;
  covers both the active-engagement path and the `engId` path.
- First `appendUserMessage` on a provisional chat sets a derived title and an
  inferred focus.
- A renamed chat (`name !== 'New chat'`) is **not** retitled on its next message.
- A second user message does **not** re-title or re-infer.
- `deriveTitle` / `inferFocus` unit tests: word-capping, punctuation cleanup,
  empty-input fallback, phase keyword match, first-phase fallback.
- Remove/replace the old `NewChatModal`-driven assertions.

## Out of scope (deferred to M2)

- Real cheap-model title generation and real focus inference (this design fixes
  the seam; M2 swaps the mock for the model call).
- Persistence of chats/titles (already M2 per HANDOVER).
